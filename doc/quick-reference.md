# 技术边界速查

[首页](../README.md) · [完整问答索引](技术学习笔记.md) · [版本与资料](references.md)

先判断机制覆盖的资源和时间范围，再选择补充的并发、重试与对账手段。

| 机制 | 可以依赖的性质 | 仍需单独分析的问题 |
| --- | --- | --- |
| ConcurrentHashMap | 所提供操作的并发安全 | 多步检查与更新是否原子 跨进程业务去重 |
| volatile | 可见性与规定的有序性 | 复合读改写操作的原子性 |
| 本地数据库事务 | 指定事务资源内的提交与回滚 | HTTP 调用 消息发送与外部副作用 |
| [Transactional Outbox](topics/outbox-rocketmq-inbox.md) | 业务与待发送事件记录在本地同事务提交 | 恢复投递、重复发送、Broker 持久化与保留期 |
| [Inbox 与唯一约束](topics/outbox-rocketmq-inbox.md#消费端如何提交-inbox-与业务) | 同一逻辑处理器按事件身份识别已提交结果 | 同事务业务修改、载荷冲突、业务效果键与记录保留 |
| [业务状态机](topics/outbox-rocketmq-inbox.md#状态机如何处理重复与乱序) | 根据合法旧状态和版本条件推进 | 缺少前序、增量副作用、跨服务业务补偿 |
| Redis 租约锁 | 在相应假设下协调持有期内的竞争 | 租约过期 旧持有者继续执行 故障切换 |
| Kafka 生产者幂等 | 特定发送会话与配置下的重试去重 | 消费重放与外部数据库业务幂等 |
| Flink Checkpoint | 支持恢复处理进度与托管状态 | Source 可重放性 Sink 提交与外部可见结果 |
| Watermark | 推动事件时间计算 | 超出预期的迟到数据与修正策略 |
| ReplacingMergeTree | 合并时按排序键和版本处理替换 | 查询前是否已去重 已累计汇总如何修正 |
| 分页导出 | 限制每批读取的数据量 | 并发数据变化 稳定排序与快照语义 |
| 唯一约束 | 阻止相同受约束键重复保存 | 去重记录与业务修改是否同事务 |
| 接口超时 | 调用方在时间预算内未得到结果 | 对方是否已经成功以及能否安全重试 |
| 任务成功状态 | 任务按自身成功条件结束 | 指标口径 数据完整性和下游对账 |
| [支付意图与尝试](topics/payment-idempotency.md) | 按订单仲裁有效支付尝试，按稳定请求身份确认远端结果 | 渠道幂等有效期、重复扣款核查、退款与人工处置 |
| [Saga 与 TCC](topics/saga-tcc-workflow.md) | 持久编排可恢复；资源预留按分支状态确认或释放 | 未知结果、补偿失败、隔离性、空回滚与防悬挂 |
| [Fencing](topics/lease-fencing.md) | 资源端原子拒绝已被更新 Epoch 取代的写入 | 令牌签发到资源端生效的窗口、所有写路径与不可逆外部调用 |
| [持久导出快照](topics/resumable-export.md) | 冻结输入值后按稳定键恢复分片进度 | 快照构建失败、对象孤儿、发布竞争、权限和保留期 |
| [快照与 CDC](topics/snapshot-cdc.md) | 使用连接器协议建立一致快照与日志边界 | 日志保留、目标连续应用前沿、删除、DDL 与源切换 |
| [按最新事实计算](topics/flink-clickhouse-consistency.md) | 按业务键和确定版本选择事实，再按口径汇总 | 相同版本冲突、删除过滤时机、已累计物化视图与发布完整性 |
| [数据库写切换](topics/online-database-migration.md) | 隔离旧写入口并追平最终位点后转交写入权威 | 遗漏写入口、新写入后的逆向同步与字段转换可逆性 |
| [任务结果发布](topics/distributed-scheduling-backfill.md) | 按运行实例、Epoch 和版本仲裁可见产物 | 底层执行取消、补数隔离、依赖就绪与跨窗口整体发布 |
