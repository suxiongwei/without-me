# 技术边界速查

[首页](../README.md) · [完整问答索引](技术学习笔记.md) · [版本与资料](references.md)

先判断机制覆盖的资源和时间范围，再选择补充的并发、重试与对账手段。

| 机制 | 可以依赖的性质 | 仍需单独分析的问题 |
| --- | --- | --- |
| ConcurrentHashMap | 所提供操作的并发安全 | 多步检查与更新是否原子 跨进程业务去重 |
| volatile | 可见性与规定的有序性 | 复合读改写操作的原子性 |
| 本地数据库事务 | 指定事务资源内的提交与回滚 | HTTP 调用 消息发送与外部副作用 |
| Redis 租约锁 | 在相应假设下协调持有期内的竞争 | 租约过期 旧持有者继续执行 故障切换 |
| Kafka 生产者幂等 | 特定发送会话与配置下的重试去重 | 消费重放与外部数据库业务幂等 |
| Flink Checkpoint | 支持恢复处理进度与托管状态 | Source 可重放性 Sink 提交与外部可见结果 |
| Watermark | 推动事件时间计算 | 超出预期的迟到数据与修正策略 |
| ReplacingMergeTree | 合并时按排序键和版本处理替换 | 查询前是否已去重 已累计汇总如何修正 |
| 分页导出 | 限制每批读取的数据量 | 并发数据变化 稳定排序与快照语义 |
| 唯一约束 | 阻止相同受约束键重复保存 | 去重记录与业务修改是否同事务 |
| 接口超时 | 调用方在时间预算内未得到结果 | 对方是否已经成功以及能否安全重试 |
| 任务成功状态 | 任务按自身成功条件结束 | 指标口径 数据完整性和下游对账 |
