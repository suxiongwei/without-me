# 内存受限时统计大文件词频

[算法目录](LeetCode.md) · [分布式设计](interview_design.md)

题设：文件约 2 GB、JVM 内存预算 512 MB，统计每个单词次数。先定义编码、分词、大小写、标点和超长词规则；只有文件大小并不能推导唯一单词数量。

## 先用流式读取约束输入内存

使用带缓冲的增量解码读取，不能一次加载整个文件；如果一行可能特别长，不能仅凭“按行读取”就保证内存有界。跨缓冲区的半个单词要保留到下一批，明确极长 token 的上限与处理规则。计数使用能覆盖总量的类型。

## 唯一词过多时做外部分区

1. 对已规范化的词计算稳定哈希，将相同词写到同一个磁盘分区。
2. 关闭并确认分区文件完整后，逐个分区在内存中聚合。
3. 某分区仍超过预算时，再分区或使用外部排序后顺序归并。
4. 合并各分区的输出；需要全局 Top K 时用有界堆继续处理。

预算还需扣除 JVM 本身、Map 条目、字符串对象和缓冲区成本。记录临时文件、阶段完成状态与输入范围，以便失败重跑；热点或恶意超长 token 需要独立约束。

## 练习边界

空文件、跨块单词、多字节编码、所有词相同、全部词不同、极长单词、磁盘不足和中途失败。这里给出算法分析，没有执行大文件实验。
