## Q11 Java 进程 CPU 高或内存持续增长 怎么排查

类型：排障题。优先级：高。

原理与做法：我先看影响范围和变更时间，确认是应用 CPU、GC 还是宿主机资源竞争。CPU 高时将高占用线程与线程栈对应，间隔采样，看是计算热点、循环还是频繁对象分配。内存增长则结合 GC 日志、堆使用趋势、对象存活和引用链，区分正常缓存、积压与泄漏。线程转储和堆转储的命令、权限与影响要结合环境，堆转储可能占用大量磁盘并暂停应用，不能无条件在线执行。

进一步思考：问“Full GC 后为什么还不降”，先核对观察的是堆、进程 RSS 还是容器内存，再看存活对象、堆外内存和内存归还策略，不直接断言一定泄漏。

## Q12 接口很慢 但数据库不慢 怎么定位

类型：排障题。优先级：高。

原理与做法：我把总耗时拆成进入应用前的等待、线程池和连接池等待、应用计算、数据库、远程调用与序列化传输。数据库某一条查询很快，仍可能存在多次重复查询或获取连接的长等待。通过同一请求标识串联分段耗时，比较正常与异常请求，再检查超时重试是否放大流量。先定位最主要耗时段，再决定优化 SQL、连接资源、并行调用或响应体。

进一步思考：问“加机器是否有效”，回答只有瓶颈在可水平扩展的应用资源时才可能有效；共享数据库或下游饱和时，增加应用实例还可能加重问题。
