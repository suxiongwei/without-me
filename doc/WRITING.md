# 文档维护约定

[首页](../README.md) · [版本与资料](references.md) · [图片素材](assets/README.md)

## 目录与职责

- `README.md`：仓库定位、知识地图、阅读路线和分类入口。
- `doc/interview_*.md` 等现有分类页：推荐顺序、专题导航、补充知识与代码入口。旧文件名继续作为稳定入口。
- `doc/topics/`：每个知识点的主要解释；同一问题选定一篇主文档，其余页面引用它。
- `doc/practice.md`：题设、输入边界、参考解法和手工走查。
- `doc/quick-reference.md`、`doc/references.md`：短结论、适用版本与官方资料。
- `src/`：已有代码示例；旧 Markdown 通过分类页引用，逐步维护内容，不为整理目录移动 Java 包。

## 正文模板

```markdown
# 主题名称

返回分类 · 相关专题

一句话说明这个主题解决什么问题。

适用版本与前提：写明环境和假设。

## 问题与最小示例

给出输入、现象或反例。

## 原理与过程

结合一张图解释正常路径与失败位置。

## 适用边界与常见误区

说明机制覆盖的资源、时间范围和额外协议条件。

## 练习与参考资料

链接到代码、练习与官方文档。
```

## 排版与链接

每篇文章使用一个一级标题；后续使用二级、三级标题，避免跳级。长文在标题下提供阅读目录；标题和列表之间留空行。核心解释直接展示，较长的参考答案可折叠，折叠标题写明具体内容。

仓库文件与图片使用相对路径；标题链接尽量使用稳定锚点。没有正文或示例的条目写明“待补充”，不要留空链接。路径避免 Windows 保留字符和大小写不一致。

## 图形规则

结构、流程和时序优先使用 Markdown 中的 Mermaid。一张图回答一个问题，通常控制在 5–8 个主要节点；用文字补充前提、失败窗口和省略项。复杂问题拆成总览与细节图。维护入口见[图解目录](DIAGRAMS.md)。

独立新图放在 `doc/assets/`，使用 `spring-transaction-sequence.svg` 这类有意义的名字。历史图片保留在 `_v_images/`，通过[素材目录](assets/README.md)按主题查找；复用时写出准确的替代文字和说明，不重复保存二进制副本。

## 内容边界与检查

明确区分接口契约、特定版本实现和示例假设。“有序、不丢、幂等、去重”等结论要写清作用范围。性能数字必须带环境、数据规模和测量方法；缺少实测时只记录分析方法。

文档变更检查路径、锚点、代码围栏和图形语法，并审阅 Git diff。静态检查不代表示例已经运行；新增验证记录写清实际执行的检查。代码的测试、编译和打包按仓库约定单独授权。
