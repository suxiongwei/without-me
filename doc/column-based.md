# 列式存储与压缩

[首页](../README.md) · [版本与资料](references.md)

列式存储按列组织数据，使只读取少量列的分析查询可以减少读取和解码量；具体物理布局由文件、数据块、编码和引擎实现决定。

列式组织与分布式部署是不同维度，不能从按列存储直接推导数据一定分散在多个节点。

同列数据类型和分布通常相近，有利于选择编码与压缩；是否使用字典取决于基数、数据类型与具体引擎。

## 数据压缩：

下面用**字典编码**说明一种压缩思路，并非所有列、所有列式引擎都采用相同方式。

比如：
对于姓名列，这列的所有数据如下：
```text
彦祖|德华|路人甲|德华|彦祖
```

对这列值去重以后，构建一张姓名列字典表，构建算法忽略，就使用自增id的方式,如下：

| id | 姓名列 |
|-----|-----|
|1| 彦祖 |
|2| 德华 |
|3| 路人甲 |

这样构建字典表，对于列存储的物理存储结构，就可以执行存储字典表中的id,而不用存储具体的值，有了字典表以后姓名列存储如下：

```text
1|2|3|2|1
```

## 列存储的查询执行过程

下面是位图过滤的一种简化模型；实际执行还可能使用稀疏索引、向量化过滤、跳数索引和延迟读取等机制。

1. N个column的过滤条件会给各个column的数据匹配的行打上1的标记
2. 将N个bitmap做与运算，就能得到满足过滤的条件的行
3. 结果汇总(select *): 拿匹配的行的index去各个列查找数据，然后进行拼接出来
